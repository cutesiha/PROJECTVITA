# 전투 뼈대 설계 (규칙에 묶이지 않는 턴제 엔진)

> 2026-11-17 작성. `01_HANDOFF_새프로젝트_환경구축.md`를 먼저 읽는다.
> 전투 규칙은 **비디님이 기획 중**이다. 이 문서는 규칙이 오기 전에 만들어 둘 뼈대다. 규칙이 오면 데이터와 몇 개의 규칙 클래스만 바꾸면 되도록 만든다.

## 1. 확정된 것과 미정인 것

**확정**
- 포켓몬식 **스탯 기반 턴제 전략** 전투다.
- **인물(플레이어블 캐릭터)이 직접 싸우고**, 인조 생물은 적이다.
- 스토리 게임 안에 들어가는 전투다. 탐색 중 조우나 스토리 이벤트로 시작하고, 결과에 따라 대사가 이어진다.
- 아트는 **일러스트 스탠딩(정지 이미지)과 이펙트**로만 연출한다. 걷기, 공격 같은 프레임 애니메이션은 넣지 않는다. 3인 팀 일정 때문이다.
- 레퍼런스는 포켓몬(규칙의 가독성)과 림버스 컴퍼니(캐릭터, 연출)다.

**미정 (비디님의 답을 기다리는 중)**
- 출전 인원, 턴 순서 방식, 스탯 종류, 타입 상성 유무, 스킬 비용 방식, 상태이상, 특수 시스템, 패배 처리, 성장 방식.

그래서 **미정인 부분은 전부 교체 가능한 지점으로** 설계한다. 일단 포켓몬과 비슷한 기본값으로 돌아가게 해 둔다.

## 2. 설계 원칙

1. **로직과 연출을 분리한다.**
   - 전투 로직은 MonoBehaviour가 아닌 순수 C#으로 만든다 (`BattleCore`).
   - 로직은 **이벤트 목록**(`BattleEvent`)을 내보내기만 한다.
   - UI와 연출은 그 이벤트를 받아서 재생한다.
   - 이렇게 하면 시뮬레이터, 리플레이, 테스트, 스킵이 공짜로 따라온다.
2. **데이터로 정의한다.** 유닛, 스킬, 상태이상, 상성, 조우는 CSV로 관리한다. 비디님이 엑셀로 수치를 고칠 수 있어야 한다.
3. **스탯은 문자열 id로 관리한다.** `Dictionary<string, int>`를 쓰고, 스탯 목록은 CSV 헤더나 정의 테이블에서 읽는다. 비디님이 스탯을 새로 만들어도 코드를 고칠 필요가 없게 한다.
4. **규칙은 인터페이스로 분리한다.** 턴 순서, 데미지 공식, 승패 판정, 행동 해결 방식이 각각 하나의 인터페이스다.
5. **과설계하지 않는다.** 1~2일 분량으로 만든다. 확실하지 않은 부분은 일단 하드코딩하고 `// TODO(규칙 대기)`로 표시한다.

## 3. 구조

```
BattleCore (순수 C#)
├─ BattleState         유닛 목록 (아군/적), 라운드 수, 난수 시드
├─ Unit                정의(id) + 현재 스탯 + 상태이상 목록 + 스킬 목록 + 게이지들
├─ SkillDef            대상 규칙 + 비용 + Effect 목록   (데이터)
├─ IEffect             Damage / Heal / ApplyStatus / ModifyStat / ChangeGauge / Custom
├─ StatusDef           지속 턴 + 트리거(OnTurnStart/OnTurnEnd/OnHit/OnAct) + Effect 목록
├─ ITurnOrderRule      기본값: 매 라운드 속도순 정렬 (포켓몬식)
├─ IActionResolver     기본값: 행동 하나씩 순서대로 해결
│                      (림버스식 합 같은 규칙이 오면 이 자리를 교체)
├─ IDamageFormula      기본값: 포켓몬식 (공격/방어 비율 × 위력 × 상성 × 난수)
├─ TypeChart           CSV 행렬 (상성이 없으면 전부 1.0)
├─ IWinCondition       기본값: 한쪽 전멸 (보스 처치, 턴 제한 등으로 확장)
├─ IEnemyAI            기본값: 가중치 랜덤 + 체력 낮은 대상 우선
└─ 출력: List<BattleEvent>   (TurnStarted, SkillUsed, Damaged, Healed, StatusApplied,
                              StatusExpired, GaugeChanged, UnitDown, BattleEnded …)

BattlePresenter (MonoBehaviour)
├─ 이벤트 큐를 순서대로 재생 (DOTween 시퀀스)
├─ 유닛 뷰: 스탠딩 일러스트, HP 바, 상태 아이콘, 데미지 숫자
├─ 명령 UI: 스킬 4칸, 대상 선택, (교체/아이템은 규칙이 정해지면)
└─ 연출: 피격 흔들림, 플래시, 스킬 컷인 (일러스트 슬라이드), 화면 흔들림
```

- 난수는 `System.Random(seed)` 하나만 쓴다. 시뮬레이터와 버그 재현을 위해서다.
- 유닛 뷰의 스탠딩은 대화용 스탠딩 스프라이트를 재사용한다. 전투 전용 일러스트는 나중에 교체할 수 있게 슬롯만 마련해 둔다.

## 4. 데이터 테이블 (초안)

파일 이름 규칙: `{System}_{Table}.csv`, UTF-8 BOM, LF. 1행은 컬럼명, 2행은 설명, 3행은 허용값이다. 4-5단계(탐색)에서 만든 CSV → SO 임포터를 같이 쓴다. 이전 팀 프로젝트의 임포터는 쓰지 않는다.

| 파일 | 주요 컬럼 |
|---|---|
| `Battle_Stat.csv` | stat_id, 표시명, 설명, min, max |
| `Battle_Unit.csv` | unit_id, 표시명, 진영(ally/enemy), 타입, 각 스탯 열…, skill_1~4, passive, portrait_id |
| `Battle_Skill.csv` | skill_id, 표시명, 설명, 타입, 위력, 명중, 비용_종류, 비용_값, 대상(single_enemy/all_enemy/self/single_ally/all_ally), effects (예: `Damage(power); ApplyStatus(burn,2,30%)`) |
| `Battle_Status.csv` | status_id, 표시명, 지속, 트리거, effects, 중첩 규칙 |
| `Battle_TypeChart.csv` | 행은 공격 타입, 열은 방어 타입, 값은 배율 |
| `Battle_Encounter.csv` | encounter_id, 적 unit_id 목록, 배경, BGM, 승리 시 Yarn 노드, 패배 시 Yarn 노드, 패배 처리(gameover/retry/continue) |

- `effects` 열은 **작은 미니 문법**으로 쓴다 (`Name(arg,…); …`). 구 프로젝트 Yarn `[seq]`와 비슷한 감각이라 작가가 익숙하다.
- 파서 오류는 임포트할 때 행 번호와 함께 경고한다.

## 5. 게임 흐름과의 연결

- `BattleLauncher.Start(encounterId, onEnd)`를 만들고, Yarn 명령 `<<battle encounterId>>`에서 호출한다.
- 전환은 4-4단계에서 만든 트랜지션(페이드나 글리치)을 쓴다.
- 끝나면 `Battle_Encounter.csv`에 지정한 승리 노드나 패배 노드로 점프한다.
- 탐색 오브젝트에서 조우할 때는 오브젝트 데이터에 `encounter_id` 열을 두면 된다.
- 전투 중 대사(보스전의 중간 대사 등)는 `BattleEvent` 트리거(예: 보스 HP 50% 이하)로 짧은 대화를 끼워 넣는다. 데모 이후에 해도 된다.

## 6. 밸런스 시뮬레이터

- 에디터 창 또는 메뉴로 만든다: `Tools > <Project> > 전투 시뮬레이터`.
- 입력: 아군 파티, 조우 id, 반복 횟수(예: 1000), 아군 AI(랜덤/탐욕)
- 출력: 승률, 평균 턴 수, 유닛별 평균 데미지와 기절률, 스킬 사용 빈도
- `BattleCore`가 순수 C#이라 화면 없이 수천 판을 돌릴 수 있다. 비디님의 수치가 오면 바로 돌려서 사용자와 비디님께 결과표를 건넨다.

## 7. 작업 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | `BattleCore`와 기본 규칙, 하드코딩 유닛 2:2 | 콘솔 로그로 전투가 끝까지 진행된다 |
| 2 | CSV 테이블과 임포터, 더미 데이터 (아군 3, 적 인조 생물 3종, 스킬 12개, 상태이상 3개) | 수치를 CSV에서 바꾸면 결과가 바뀐다 |
| 3 | `BattlePresenter` (임시 스탠딩, HP 바, 스킬 4칸, 대상 선택, 데미지 숫자, 흔들림) | 마우스로 한 판을 끝까지 플레이할 수 있다 |
| 4 | 흐름 연결 (Yarn `<<battle>>` → 전투 → 승패 노드, 탐색 오브젝트 → 조우) | 탐색 → 전투 → 대화 루프가 이어진다 |
| 5 | 시뮬레이터 | 1000판 결과표가 나온다 |
| 6 | 비디님의 규칙 반영 | 양식 답변에 맞게 규칙 클래스와 데이터를 교체한다 |

더미 데이터에는 세계관 고유명사를 쓰지 않는다 (`Ally_A`, `Enemy_Construct_1` 등). 캐릭터와 적 디자인은 비디님 영역이다.

## 8. 비디님께 보낸 전투 기획 양식의 항목 (답이 오면 매핑)

| 양식 항목 | 코드 매핑 |
|---|---|
| 출전 인원, 교체 | `BattleState` 슬롯 수, 교체 명령 |
| 턴 방식 | `ITurnOrderRule`, `IActionResolver` |
| 스탯 목록 | `Battle_Stat.csv` |
| 타입 상성 | `Battle_TypeChart.csv` |
| 스킬 개수, 비용, 종류 | `Battle_Skill.csv`, 비용 처리 |
| 상태이상 | `Battle_Status.csv` |
| **특수 시스템** (비디님이 구상 중인 것) | 대부분 게이지 + 트리거 + `IActionResolver`의 조합으로 표현된다. 필요하면 전용 규칙 클래스를 추가한다 |
| 승패, 패배 처리 | `IWinCondition`, `Battle_Encounter.csv`의 패배 처리 |
| 성장 | 데모 이후 (레벨, 장비, 스킬 해금) |
| 캐릭터별 시트 | `Battle_Unit.csv`, `Battle_Skill.csv`의 행 |
