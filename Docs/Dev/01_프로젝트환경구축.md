## 2. 확정된 결정 (다시 논의하지 않는다)

1. **이전 팀 프로젝트(BlackJokerTrials)의 코드는 쓰지 않는다.** PAVDUP이 작성한 Devdup, DOS, HelpDoNyang 계열 코드와 프리팹, 그리고 그 레포의 유료 에셋(Pixel Crushers Dialogue System, Text Animator, DOTween Pro)도 해당된다. 복사하지 않고, 열어 보지 않아도 된다. 필요한 내용은 이 문서들에 있다.
2. **대사 시스템은 처음부터 새로 만든다.** 대사 언어는 **Yarn Spinner** (무료, MIT)를 쓴다.
3. 전투는 **인물이 직접** 하고, 인조 생물은 적으로 나온다.
4. 주인공은 오리지널 여주인공이다. 이름과 서사는 비디님이 짜 온다.
5. 탐색은 **포인트앤클릭**이다.
6. **전투 규칙은 비디님이 기획 중**이다. 엑셀 양식(`전투기획양식_비디.xlsx`)을 전달했다.
7. 기획(스토리, 캐릭터, 전투 규칙)은 비디님께 맡긴다. AI가 대신 확정하지 않는다.

## 3. 사용자의 작업 방식

- 지난 팀 프로젝트는 역할 쪼개기와 회의로 몇 주씩 소모하다가 무산됐다. **빠르게 만들고, 빌드로 판단한다.**
- 임시 리소스로 먼저 만든다. 최종 아트는 같은 파일명으로 덮어씌운다.
- 수치와 실행 조건은 데이터(CSV, Yarn)로 관리한다.
- 사용자는 학교 PC에 **파섹**으로 접속해서 작업한다. 화면에 렉이 있다.
  - 에디터에서 손으로 하는 UI 배치나 인스펙터 연결은 최소화한다. -> 사실 상관없다. 에디터에서 손으로 해야되면 그렇게 해도 된다.
  - 가능하면 **에디터 스크립트(메뉴 하나로 씬, 프리팹, UI를 생성)** 로 만든다.
- 곧 새 노트북으로 옮긴다. 경로나 환경에 PC별 의존이 생기지 않게 한다.
- 브랜치를 만들거나 커밋, 푸시하는 일은 사용자가 요청하거나 이 문서의 단계에 명시된 경우에만 한다. 4-1단계의 초기 레포 생성은 명시된 경우다.

### 4-1. 기본 세팅

**먼저 사용자에게 물어볼 것**
- 학교 PC에 설치된 Unity 버전
- 프로젝트를 둘 경로
- GitHub 레포 이름과 공개 여부 (비공개 추천)

**Unity**
- 설치된 Unity 6 LTS 중 최신을 쓴다. 구 프로젝트는 6000.0.63f1이었다. 새 노트북에도 같은 버전을 설치하도록 버전을 CLAUDE.md에 기록한다.
- 템플릿은 **Universal 2D (URP)** 다.
- **OneDrive 밖, 영문 경로**에 만든다 (예: `D:\Dev\ProjectVita`). OneDrive 동기화는 Library 폴더 잠금과 지연을 일으키고, 한글 경로는 일부 빌드 도구에서 문제를 일으킨다.
- Player Settings
  - 기준 해상도는 1920×1080, 창 모드다.
  - Active Input Handling은 **Input System Package (New)** 하나만 쓴다.
  - Company와 Product 이름은 임시 값으로 둔다.
- 한글 폰트
  - Pretendard 또는 Noto Sans KR 같은 OFL 폰트를 쓴다 (라이선스 파일도 함께 넣는다).
  - TMP 폰트 에셋은 Dynamic으로 시작한다.
  - TMP Settings에서 **"Use Modern Hangul Line Breaking Rules"를 켠다.** 끄면 한글이 단어 중간에서 줄바꿈된다.
  - Dynamic 폰트 에셋은 플레이하는 동안 커진다. 커밋 전에 비우는 메뉴를 만들어 두거나, 나중에 KS X 1001 2350자로 Static 아틀라스를 굽는다.

**폴더 구조**

```
<RepoRoot>/                       ← git 루트 (= Unity 프로젝트 루트로 해도 됨)
├─ Assets/
│   ├─ _Project/
│   │   ├─ Dialogue/              ← ★ 작가가 만지는 유일한 폴더 (.yarn)
│   │   │   ├─ Prologue/
│   │   │   ├─ Chapter1/
│   │   │   └─ _Example/          ← 예시, 문법 체크용
│   │   ├─ Art/
│   │   │   ├─ Characters/<이름>/  ← 스탠딩 (표정별 PNG)
│   │   │   ├─ Backgrounds/
│   │   │   ├─ CG/
│   │   │   └─ UI/
│   │   ├─ Audio/ (BGM, SFX)
│   │   ├─ Data/                  ← CSV (탐색, 전투, 에피소드 목록)
│   │   ├─ Prefabs/
│   │   ├─ Scenes/
│   │   ├─ ScriptableObjects/
│   │   └─ Scripts/               ← 네임스페이스 <ProjectName>.*
│   ├─ Plugins/
│   └─ ThirdParty/
├─ Docs/                          ← 작가용 가이드, 문법표
├─ Tools/                         ← VS Code 워크스페이스, 스니펫 등
└─ CLAUDE.md
```

- 작가가 Unity를 몰라도 되도록, **작가는 `Assets/_Project/Dialogue/` 폴더만 만진다.** VS Code 워크스페이스 파일(`Tools/Dialogue.code-workspace`)이 이 폴더만 열게 한다.
- `.yarn` 파일은 Yarn Spinner가 임포트하려면 Assets 안에 있어야 한다.

**Git**
- `.gitignore`는 Unity 표준 템플릿을 쓴다 (Library, Temp, Logs, obj, Build(s), UserSettings, `*.csproj`, `*.sln`, `.vs`, `.idea`).
- `.gitattributes`
  - `* text=auto`
  - `*.yarn text eol=lf`, `*.csv text eol=lf`, `*.cs text eol=lf`
  - Unity YAML(`*.unity`, `*.prefab`, `*.asset`, `*.meta`)은 `text eol=lf`
  - 이미지와 오디오는 `binary`
- Git LFS는 처음에는 쓰지 않는다. 원본 PSD나 CLIP은 레포 밖(구글 드라이브)에 두고, 레포에는 내보낸 PNG만 넣는다. 레포가 1GB에 가까워지면 다시 검토한다.
- 커밋 메시지 형식은 `type : message` (`init`, `feat`, `fix`, `minor`)다.
- GitHub 레포를 만들고 첫 커밋을 푸시한다 (사용자 계정, 비공개 추천).

**브랜치**
- `main`: 사용자가 관리하는 안정 브랜치다. 코드와 씬, 그리고 반영이 끝난 대사가 있다.
- `dialogue`: 팀원(비디, 두부)이 대사를 올리는 브랜치다. 팀원은 `Dialogue/` 폴더의 `.yarn`만 커밋한다.
- 사용자가 `dialogue`를 `main`으로 주기적으로 머지한다. 작가가 쓴 `// 연출 메모`를 실제 명령으로 바꾸는 작업은 사용자가 `main`에서 한다.
- **`.meta` 파일은 사용자만 커밋한다.** 작가가 새 `.yarn` 파일을 만들면 `.meta`가 없다. 사용자가 Unity에서 열 때 생성되고, 사용자가 커밋한다. 두 사람이 같은 파일의 `.meta`를 각자 만들면 GUID가 충돌한다.
- 아트 파일을 어느 브랜치로 받을지는 아직 정하지 않았다. 필요해지면 사용자에게 묻는다.

**완료 기준**: 빈 씬이 플레이되고, GitHub에 `main`과 `dialogue`가 있고, 새 노트북에서 clone해서 열어도 바로 동작한다.

### 4-2. 대사 스크립트 시스템

**목표**: 작가가 `.yarn`에 대사를 쓰고 사용자가 pull해서 Unity를 열면, **그 대사가 바로 해당 에피소드에서 나온다.** 별도의 변환이나 임포트 작업이 없어야 한다.

**Yarn Spinner 설치**
- **Yarn Spinner for Unity** 최신 안정판을 쓴다. 설치 방법(OpenUPM, Git URL, Asset Store 무료판)은 설치 시점에 공식 문서로 확인한다.
- Yarn Project 에셋 하나가 `Dialogue/**/*.yarn`을 전부 포함하게 한다. 그러면 새 파일을 추가해도 자동으로 들어간다.
- Unity는 파일 변경을 감지해서 자동으로 재임포트한다. 플레이 중 핫리로드는 7단계 편의 기능으로 미룬다.

**작가용 문법 (최소한으로)**

```yarn
title: Prologue_Start
---
// 배경: 비 오는 폐허, 밤
// BGM: 잔잔하고 불길하게
???: 거기 누구 있어?
주인공: ...여긴 어디지?
// 주인공 놀란 표정, 화면 살짝 흔들림
주인공: 사람이 있었어?
-> 대답한다
    주인공: 네, 여기 있어요.
-> 숨는다
    // 발소리 효과음
    <<jump Prologue_Hide>>
===
```

- 작가는 `화자: 대사`, 선택지 `->`, 그리고 `// 연출 메모`만 알면 된다. Yarn의 `//`는 주석이라 게임에 나오지 않는다.
- 사용자가 나중에 `//` 메모를 `<<bg ...>>`, `<<show ...>>` 같은 명령으로 바꾼다.
- 화자가 없는 줄은 나레이션이다. 이름표를 숨긴다.

**Yarn 함정 (작가 가이드에도 넣는다)**
- 나레이션 줄에 `:`가 있으면, 그 앞부분이 화자 이름이 된다. 문장을 바꾸거나 `\:`로 쓴다.
- `#`은 태그가 시작되는 기호라서, 그 뒤가 잘린다. `\#`로 쓴다.
- `[ ]`는 마크업, `{ }`는 변수다. 대사에 쓰려면 `\[`, `\{`로 쓴다.
- 노드 이름(`title:`)은 영어, 숫자, `_`만 쓴다.

**씬과 에피소드 연결**
- 에피소드 단위는 프롤로그, 챕터1-1, 챕터1-2 … 다.
- 사용자는 "프롤로그 씬, 챕터1-ㅇㅇ 씬 등과 연결돼서 나오는 대사"를 원한다. 기본 설계는 이렇다.
  - `Data/Episodes.csv`: `episode_id, 표시명, unity_scene, start_node, next_episode`
  - Unity 씬은 모드 단위로 만든다 (`Title`, `Story`, 이후 `Exploration`, `Battle`).
  - 에피소드마다 Unity 씬을 따로 만들고 싶으면 `unity_scene` 열로 지정한다. 씬에 `EpisodeStarter`(시작 노드 지정)를 두는 방식도 지원한다.
  - 노드 이름 규칙: `{EpisodeId}_{장면}` (예: `Prologue_Start`, `Ch1_01_Start`)
  - 에피소드 이동은 Yarn 명령 `<<episode Ch1_01>>`로 한다. 에피소드 목록을 보고 씬 전환이 필요하면 전환한다.
- **이 설계는 사용자에게 한 번 확인받고 만든다.** Unity 씬을 에피소드마다 만들지, 모드 단위로 만들지 묻는다.

**이 단계에서 만들 최소 화면**
- 대사창, 이름표, 클릭이나 Space로 넘기기, 선택지
- 아직 디자인은 하지 않는다. 4단계에서 입힌다.
- 이 단계에서는 명령을 **로그만 찍는 빈 구현**으로 등록한다: `<<bg>>`, `<<show>>`, `<<hide>>`, `<<bgm>>`, `<<sfx>>`, `<<fade>>`, `<<wait>>`, `<<shake>>`, `<<cg>>`, `<<episode>>`. 문법이 먼저 굳어야 작가 가이드를 쓸 수 있다.

**완료 기준**
- `Dialogue/_Example/Example.yarn`을 고치고 Unity로 돌아와 플레이하면, 바뀐 대사가 나온다.
- 에피소드 목록에서 프롤로그 → 챕터1-1로 이어진다.

### 4-3. 팀원 교육 자료

비디님과 두부님은 Git과 Unity를 전혀 모른다. 사용자가 직접 가르칠 예정이고, 이 단계에서는 그 자료를 만든다.

**먼저 사용자에게 물어볼 것**: 자료를 어떤 형식으로 줄지 정한다. 비디님은 Notion을 안 쓰고 포스타입이 편하다. PDF, 워드, 이미지, 포스타입 글 중에서 고른다.

**자료에 넣을 내용**
1. **설치**
   - VS Code
   - Yarn Spinner 확장 (문법 색칠, 노드 그래프, 미리보기)
   - GitHub Desktop
2. **GitHub Desktop 사용법**
   - 처음 한 번: clone, `dialogue` 브랜치 선택
   - 매번: Fetch/Pull → 작성 → Commit → Push
   - 충돌이 났을 때는 혼자 해결하지 말고 사용자에게 연락한다
3. **대사 쓰는 법**
   - 4-2의 문법을 한 장짜리 표로 정리한다
   - `// 연출 메모` 쓰는 요령 (배경, BGM, 표정, 효과음, 화면 효과)
4. **브라우저에서 미리 돌려 보기**
   - Unity 없이 Yarn Spinner의 웹 플레이그라운드(Try Yarn Spinner)에 붙여 넣으면 분기를 확인할 수 있다
   - 정확한 주소는 확인해서 넣는다

### 4-4. 최소 VN (UI, 메뉴, 연출, 트랜지션)

**참고할 게임과 가져올 감각** (모방하지 말고 감각만 가져온다. 에셋, 레이아웃, 로고를 베끼지 않는다)

| 게임 | 가져올 감각 |
|---|---|
| 림버스 컴퍼니 | 각진 UI, 어두운 바탕에 강한 포인트 색, 굵은 타이포, 글리치와 노이즈 연출, 스탠딩 컷인 |
| 단간론파 | 과감한 색 대비, 대사 강조 연출 (확대, 흔들림, 글자 효과), 카메라 줌과 컷 전환, 빠른 템포 |
| 네가 죽어 | 어둡고 불길한 톤, 단정한 대사창, 정적과 긴장을 살리는 연출, 화면 암전 |

**만들 것**
- **대사창**: 이름표, 타이핑 효과 (직접 구현), 다음 표시 아이콘, 나레이션 모드
- **스탠딩**
  - 명령: `<<show 이름 표정 위치>>`, `<<hide 이름>>`, `<<move>>`, `<<face 이름 표정>>`
  - 표정 변경은 줄 태그로도 지원한다: `주인공: 대사 #face:놀람`
  - 말하는 사람을 강조하고, 나머지는 어둡게 한다
- **배경과 CG**: `<<bg 이름 [전환]>>`, `<<cg 이름>>`, `<<cg off>>`
- **트랜지션**: 페이드 (검정, 흰색), 컷, 와이프 또는 글리치 1종. `<<fade out 0.5>>`, `<<fade in 0.5>>`
- **화면 효과**: `<<shake 세기 시간>>`, 플래시, 비네트
- **오디오**: `<<bgm 이름 [페이드]>>`, `<<bgm stop>>`, `<<sfx 이름>>`
- **메뉴**: 타이틀 (시작, 이어하기, 설정, 종료), 일시정지 메뉴, 설정 (음량, 텍스트 속도, 창 모드)
- **세이브와 로드**: 최소한으로 에피소드와 노드, 변수만 저장한다. 슬롯 UI는 7단계로 미룬다.
- **리소스 찾기**: 이름 규칙을 정해서 이름만으로 찾는다 (Resources 또는 Addressables).
  - 캐릭터 정의는 ScriptableObject로 한다: 이름 (= Yarn 화자 이름), 표정별 스프라이트, 이름표 색
  - 임시 그림은 단색 PNG와 이름표로 만든다. 다른 게임이나 이전 프로젝트의 그림은 쓰지 않는다.
- 트윈은 **DOTween 무료판** 또는 직접 만든 코루틴을 쓴다.

**완료 기준**: `Example.yarn` 하나로 모든 명령이 화면에 나오고, 타이틀 → 프롤로그 → 챕터1-1 → 타이틀로 한 바퀴가 돈다.

### 4-5. 포인트앤클릭 탐색과 CSV

- 구조: 지도 화면 → 장소 화면 → 오브젝트와 인물 클릭 → Yarn 노드 실행
- 장소는 프리팹이다. 배경 일러스트와 클릭 영역(투명 버튼 또는 콜라이더)으로 구성하고, 각 영역에 `object_id`를 둔다.
- CSV (`Data/`, UTF-8 BOM, 1행 컬럼명)
  - `Exploration_Location.csv`: location_id, 표시명, 배경, 진입 시 Yarn 노드, 해금 조건
  - `Exploration_Object.csv`: object_id, location_id, 표시명, Yarn 노드, 표시 조건, 1회성 여부
- 조건은 Yarn 변수(`$변수명`)로 판정한다. 조사한 오브젝트는 자동 변수(`{object_id}_seen`)로 기록한다.
- CSV를 ScriptableObject로 바꾸는 임포터를 만든다. 메뉴 하나로 실행되고, 존재하지 않는 Yarn 노드나 id 중복을 경고한다.
- Yarn 명령 `<<explore 장소id>>`로 대사에서 탐색으로 넘어가고, 대사가 끝나면 탐색으로 돌아온다.
